# Проверка конфигурации

Две команды проверяют конфигурацию до того, как от неё будет зависеть
настоящее письмо: `--check-config` читает её, ничего не отправляя,
`--probe` отправляет тестовое письмо через цели. Куда идут записи
настоящего письма, описано на странице [Журнал](logging.ru.md).

## Проверка файла

`--check-config` не читает ни stdin, ни спул и ничего не отправляет,
пишет замечания в stderr и завершается с кодом 0 без ошибки и 78 с
ошибкой. Аргументов не принимает (64). Запускать её могут root,
пользователь `mailcrier` и вызывающая программа без бита setgid.

`mailcrier --check-config` загружает конфигурацию и строит её цели так
же, как любой вызов, поэтому находит каждую ошибку, из-за которой письмо
было бы отклонено с кодом 78, и добавляет предупреждения о том, что
загружается, но может работать не так, как задумано. Ошибки и
предупреждения идут в stderr по одному на строку, последняя строка их
подсчитывает; stdout остаётся пустым. Вызов останавливается на первой
ошибке: после ошибки в файле больше ничего не сообщается, а после ошибки
цели (шаблон, который не разбирается, неизвестный сервис shoutrrr, URL
ntfy без темы) предупреждения о файле всё равно выводятся. Ошибка цели
указывает на строку её ключа; шаблон из `template_file` назван путём
этого файла, и строка после пути - строка этого файла. Код выхода - 78
при ошибке и 0 в остальных случаях, с предупреждениями тоже. Запускайте
команду от root после каждого изменения конфигурации: root, как любой
другой пользователь, получает группу исполняемого файла с битом setgid,
поэтому проверки прав ниже выполняются.

```toml
[target.ops]
type = "http"
url = "https://discord.com/api/webhooks/123/abc/slack"
preset = "slack-webhook"

[target.backup]
type = "discord"
url = "https://discord.com/api/webhooks/456/def"

[target.phone]
type = "ntfy"
url = "https://ntfy.example.org/"

[[route]]
subject = "*backup*"
targets = ["ops", "phone"]
```

| Предупреждение | Причина | Что делать |
|---|---|---|
| `file of key "token_file" is readable by all users` (или `url_file`) | у файла секрета есть бит чтения для остальных | `chmod o-r`, группа-владелец `mailcrier`, режим `0640` |
| `file is readable by all users and holds secrets` | конфигурация содержит `token`, `url`, `headers`, `query` или `path` в явном виде и имеет бит чтения для остальных | `chmod 0640` или перенесите секреты в файлы `*_file` |
| `file of key "..." is not readable by the group of the binary, every call of another user exits 78` | `*_file` или `template_file`, или сама конфигурация, принадлежит группе исполняемого файла без бита чтения для группы или другой группе без бита чтения для остальных: ядро применяет биты только одного класса | `chgrp mailcrier` и `chmod g+r` |
| `directory of key "..." is not searchable by the group of the binary, ...` | каталог на пути к файлу, включая `/`, принадлежит группе исполняемого файла без бита поиска для группы или другой группе без бита поиска для остальных | `chmod o+x` или группа `mailcrier` с `g+x` |
| `shoutrrr service "telegram" has a native target type "telegram"` (также `slack`, `discord`, `ntfy`) | цель shoutrrr отправляет простой текст без экранирования, ограничений длины и файлов сервиса | используйте тип цели этого сервиса |
| `preset "slack-webhook" on a Discord host does not disable mentions` | Slack-совместимый адрес вебхука Discord позволяет `@everyone` из письма оповестить весь канал | используйте тип `discord` |
| `routes have no rule without conditions` | маршруты есть, но ни одно правило не подходит ко всем письмам | добавьте последним `[[route]]` только с `targets`; условие вроде `subject = "*"` не считается |
| `no route names this target` | маршруты есть, и ни маршрут, ни `telegram_direct` не называет цель | добавьте её в маршрут или удалите |
| `first element of key "argv" is not an executable file` | программы цели `exec` нет или у неё нет бита выполнения | установите её, `chmod +x` |
| `template fails on the sample message, the built-in one is used` | шаблон из конфигурации не срабатывает или не укладывается в лимит цели | исправьте шаблон; до тех пор вызовы используют встроенный |
| `request template fails on the sample message, the target gets nothing` | не срабатывает шаблон `path`, `query` или `headers` | исправьте шаблон; до тех пор цель не получает писем |
| `the sample message does not render, the target gets nothing` | встроенный шаблон не укладывается в `max_text`, для JSON или MarkdownV2 | увеличьте `max_text` |

Четыре проверки прав выполняются, только если к процессу применился бит
setgid, а так бывает у root и у пользователя `mailcrier` с другой
основной группой; без бита (контейнер, исполняемый файл без бита,
`sudo -u mailcrier` с основной группой `mailcrier`) они пропускаются,
потому что неизвестна группа, которая читает файлы. Они читают только
режим и группу-владельца: списки контроля доступа не видны, а если
каталог - символическая ссылка, проверяется каталог, на который она
указывает, но не каталоги на пути к нему. Проверка `argv` выполняется с
идентификаторами того, кто вызвал `--check-config`, а хук запускается с
идентификаторами вызывающей программы каждого письма.

Предупреждения, которые заканчиваются на "sample message", возникают,
когда шаблоны каждой цели выполняются на встроенном образце письма - том,
что отправляет `--probe`, - без отправки и без запуска хуков. В образце
нет вложений, HTML, длинного текста и Bcc, поэтому ветки шаблона для них
не проверяются; а URL, который цель `http` строит из текста шаблона
`path`, проверяется только при отправке.

## Пробная отправка

`--probe` отправляет образец письма с темой `mailcrier probe from <host>`
во все цели конфигурации, а с `--probe -- name ...` - в названные цели
(неизвестное имя даёт код выхода 64 до какой-либо отправки; имена идут
после `--`, потому что имя может начинаться с `-`). Это настоящие
уведомления, и хуки `exec` запускаются. Маршруты, правила `[[suppress]]`
и личные чаты не применяются. Команда не читает stdin, не трогает спул и
не запускает прогон очереди. В stdout идёт одна строка logfmt на цель,
например `target=mm class=temp status=503 err="Service Unavailable"`;
шаблон, который не сработал и был заменён встроенным, показывается как
`template=fallback` со статусом 0, а ошибку шаблона показывает
`--check-config`. Конфигурация, которую команда не может использовать,
выводится в stderr как `mailcrier: <error>`, а записи пробной отправки в
журнале содержат `mode=probe`. Код выхода - 0, если каждая цель приняла
письмо, 69, если одна его отклонила, и 75, если у одной временная
ошибка, а отклонивших нет. Запускать её могут root, пользователь
`mailcrier` и вызывающая программа без бита setgid. Почтовые флаги вроде
`-f` или `-t` игнорируются, а из нескольких опций режима действует
последняя.
