# Длинные письма

Как обрезается текст сверх лимита цели и ключи `on_long`, `long_file`,
`max_text` и `max_lines`, которые решают, что получает цель. Лимиты
каждого сервиса указаны на странице его типа в разделе
[Цели](targets.ru.md).

## Как режется текст

Текст длиннее, чем принимает цель, обрезается: сначала тема длиннее
четверти лимита (не меньше 64 единиц цели) обрезается по слову и
заканчивается на `...`, затем список вложений, затем тело, которое
заканчивается уведомлением `truncated`. Лимит считается так, как его
считает сервис, после экранирования. Если остальной текст, включая хост
и отправителя, сам по себе слишком длинный, текст обрезается жёстко;
для Telegram - между тегами и сущностями, с закрытием открытых тегов.
Что идёт вместе с обрезанным текстом, задаётся для каждой цели, как
описано ниже.

## Что идёт вместе с обрезанным текстом

```toml
[target.ops-telegram]
type = "telegram"
token_file = "/etc/mailcrier.d/telegram.token"
chat_id = -1001234567890
on_long = "file"        # необязательно: file | truncate | blockquote
long_file = "text"      # необязательно: text (message.txt) | eml (message.eml)
max_text = 2000         # необязательно, ниже лимита сервиса
max_lines = 40          # необязательно, строки тела в тексте
```

- Текст сверх лимита цели обрезается, как описано в разделе [Как режется
  текст](#как-режется-текст). С `on_long = "file"`, значением по
  умолчанию, цель, которая отправляет файлы, получает полный текст как
  `message.txt` (`text/plain`, UTF-8, письмо в простом оформлении без
  лимита) первым файлом, первым в списке вложений текста, а обрезанное
  тело текста заканчивается уведомлением `truncated`.
  `long_file = "eml"` вместо этого отправляет само письмо как
  `message.eml`, в том виде, в каком оно прочитано, без полей `Bcc` и
  `Resent-Bcc`; письмо из очереди отправляется так же.
- `on_long = "truncate"` отправляет только обрезанный текст; так же
  поступает цель без файлов (`http`) и цель, лимит файла которой полный
  текст превышает. Тело тогда заканчивается уведомлением
  `truncated_size`, например `[truncated, 1.9 MiB in full]`, с размером
  `message.txt`.
- `on_long = "blockquote"` - это `file`, где обрезанное тело идёт в
  раскрываемой цитате Telegram, которая показывает несколько строк, пока
  её не откроют; у других целей такого блока нет, и для них это `file`.
- `max_text` заменяет лимит текста сервиса, в его единицах: символы
  Telegram и документов `mattermost` и `generic-json`, единицы UTF-16
  Discord, Slack и документа `slack-webhook`, байты ntfy. Значение выше
  лимита сервиса берётся как есть, и сервис отклоняет более длинный
  текст. Для `http` лимит покрывает весь документ JSON: лимит, слишком
  малый для документа без тела и темы, даёт цели постоянную ошибку.
  `max_lines` обрезает тело, в котором строк больше, после этого числа
  строк и считает текст обрезанным; пустые строки в конце не считаются.
  Оба значения должны быть положительными; `long_file`, как и `on_long`,
  не ключ `http`.
- Цель Telegram, которая отвечает 400 на текст из-за разметки, которую
  не может разобрать, или из-за текста сверх лимита, получает полный
  текст ещё раз одним файлом, без текста и подписи, каков бы ни был её
  `on_long`; журнал записывает `text rejected, sent as file`
  (warning). Если не удаётся и это, запись -
  `text rejected, file failed too` (warning), и цель завершается
  ошибкой второй попытки. Считается любой ответ 400, в том числе из-за
  неверного `chat_id`, что стоит ещё одного запроса.
