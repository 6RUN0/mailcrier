# Контейнеры

Работа mailcrier там, где бит setgid не действует: в контейнере, в юните с
`NoNewPrivileges=yes`, в виде скопированного исполняемого файла. Установка с
битом setgid описана на странице [Привилегии](privileges.ru.md).

- Если бит setgid не действует, исполняемый файл работает с id своей
  вызывающей программы, и для контейнеров это обычный режим: Docker с
  `--security-opt no-new-privileges`, Kubernetes с
  `allowPrivilegeEscalation: false`, юнит systemd с
  `NoNewPrivileges=yes` или `RestrictSUIDSGID=yes` или исполняемый файл,
  скопированный без бита. Тогда конфигурация и её файлы `*_file` должны
  быть доступны вызывающей программе на чтение (для PHP-FPM, например,
  `0640 root:www-data`), `--config` и `MAILCRIER_CONFIG` работают, а
  секреты, смонтированные как файлы (секреты Docker или Kubernetes),
  передаются через `*_file`. Для PHP задайте
  `sendmail_path = /usr/sbin/sendmail -t -i`, где `/usr/sbin/sendmail` -
  ссылка на исполняемый файл, и передайте переменную строкой
  `env[MAILCRIER_CONFIG] = /run/secrets/mailcrier.conf` в конфигурации
  пула. Каталог спула, `/var/spool/mailcrier`, если `[spool] dir` не
  называет другой, должен существовать и быть доступен вызывающей
  программе на запись (том, если письма в очереди должны пережить
  контейнер); без него временная ошибка завершает вызов с кодом 73, а
  `dir = ""` выключает спул.
- Память одного вызова как пик его cgroup (Docker, `--cpus=1`, amd64,
  Go 1.27.2): письмо до 100 KiB занимает меньше 15 MB, а 20 таких вызовов
  одновременно заняли вместе 58 MB. Письмо в 10 MiB, наибольшее из
  читаемых, занимает примерно до 40 MB для цели `exec`, около 100 MB с
  одной целью Telegram, около 200 MB с 3 и около 420 MB с 10: каждая цель
  с лимитом текста выполняет шаблон над всем телом. Одновременные вызовы
  складываются. Вызов, убитый ядром из-за памяти, возвращает своей
  вызывающей программе код 137. Если он убит во время записи письма в
  спул, письмо теряется, а файлы, оставшиеся в `tmp/`, удаляются через
  час. Если позже, письмо остаётся в `queue/`, и каждый повтор снова
  выполняет для него шаблоны, пока `queue_ttl` не переместит его в
  `failed/`.

## Что проверить

Что нужно контейнеру помимо пунктов выше; каждый пункт описан там, где
ему место:

- Журнал: без `/dev/log` записи идут в stderr, а PHP-FPM передаёт их
  дальше только с `catch_workers_output = yes`, см.
  [Журнал](logging.ru.md#куда-идут-записи).
- Очередь: без демона cron или таймера её запускают только сами вызовы;
  `mailcrier -q` из планировщика вроде supercronic повторяет остальное,
  см. [Спул и очередь](spool.ru.md#прогоны-очереди).
- Полный пример со спулом на томе и секретами в `/run/secrets`:
  [`packaging/examples/container.conf`](../packaging/examples/container.conf),
  устанавливается как `/usr/share/doc/mailcrier/examples/container.conf`.

English: [containers.md](containers.md).
