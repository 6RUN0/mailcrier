# shoutrrr

Тип `shoutrrr` отправляет через сервис библиотеки shoutrrr. Ключи,
которые принимает любая цель, и как классифицируется ошибка:
[Цели](../targets.ru.md).

```toml
[target.bus]
type = "shoutrrr"
url_file = "/etc/mailcrier.d/bus.url"   # URL сервиса, gotify://host/token
```

Цель этого типа отправляет одно сообщение через сервис библиотеки
shoutrrr (github.com/nicholas-fedor/shoutrrr v0.21.1), который выбирается
по схеме URL: `gotify`, `matrix`, `teams`, `pushover`, `smtp`, `generic`
и другие из её документации. Текст - текст простого шаблона (тема, хост,
отправитель, тело), без файлов и без заголовка; своего лимита длины у
mailcrier нет, каждый сервис обрезает или делит длинный текст так, как
это делает библиотека. Неизвестная схема или URL, который сервис
отклоняет, дают код выхода 78 при загрузке конфигурации. `matrix`
принимает только токен доступа (`matrix://:token@host`): с именем
пользователя библиотека входит на сервер во время загрузки конфигурации,
вне `http_timeout` и `deadline`, поэтому такой URL даёт код выхода 78,
не обращаясь к серверу. Ошибка после HTTP-ответа вне 2xx
классифицируется по статусу, как у других целей; перенаправление не
выполняется и даёт постоянную ошибку, даже там, где библиотека сочла бы
его успехом; любая другая ошибка временная, и письмо остаётся в очереди
до `queue_ttl`. Сервисы, которые отправляют по HTTP, используют
`http_timeout` и
[правило прокси](../configuration.ru.md#таймауты-и-прокси); `smtp`,
`xmpp` и `mqtt` открывают свои соединения без прокси, ограниченные только
`deadline`. Тексты ошибок библиотеки могут цитировать URL, который в
журнале маскируется, как любой URL.
