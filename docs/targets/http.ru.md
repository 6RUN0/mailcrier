# HTTP и Mattermost

Тип `http` отправляет один запрос на письмо: во входящий вебхук
Mattermost или Slack, в JSON API или пингом GET. Ключи, которые принимает
любая цель, и как классифицируется ошибка: [Цели](../targets.ru.md);
шаблоны тела, пути, параметров запроса и заголовков:
[Шаблоны](../templates.ru.md).

```toml
[target.mm]
type = "http"
preset = "mattermost"           # mattermost | slack-webhook | generic-json
url_file = "/etc/mailcrier.d/mm.url"
username = "mailcrier"          # необязательно, только mattermost
channel = "alerts"              # необязательно, только mattermost

[target.api]
type = "http"
preset = "generic-json"
url = "https://api.example.org/notify"
method = "PUT"                  # GET, PUT, PATCH или POST, если не задан

[target.api.headers]            # необязательно, значения - шаблоны
Authorization = "Bearer api-token"

[target.ping]
type = "http"
method = "GET"
url = "https://status.example.org/api/push/abc"
path = "/{{ pathSegment .Hostname }}"   # необязательно, после пути url

[target.ping.query]             # необязательно, значения - шаблоны
status = "down"
msg = "{{ .Subject | truncate 200 }}"
```

Цель этого типа отправляет один запрос с JSON-документом своего пресета
или своего шаблона (см. [Шаблоны](../templates.ru.md)), с `Content-Type:
application/json` и без файлов. Задаётся ровно один из ключей `preset`,
`template` и `template_file`. `method` - `POST` (по умолчанию), `GET`,
`PUT` или `PATCH`, заглавными; любое другое значение даёт код выхода 78.
`GET` не отправляет ни тела, ни Content-Type, поэтому не принимает ни
`preset`, ни `template`, ни `template_file`, ни `max_text`, ни
`max_lines`; письмо доходит до сервиса через `path`, `query` и заголовки.
`slack-webhook` обрезается до 40000 символов - столько хранит Slack;
`mattermost` - до 16383 символов, потому что более длинный текст
Mattermost делит на несколько сообщений в любом месте, в том числе внутри
блока кода; у `generic-json` лимита нет. Обрезанный текст заканчивается
размером полного, потому что файл с ним не отправляется. `mattermost`
публикует `{"text": ...}` с темой, хостом, отправителем и телом в Markdown,
обезвреженными `@channel`, `@all` и `@here` и с `username` и `channel`,
если они заданы; заданный `channel` не может быть пустым, пробельные
символы вокруг него отбрасываются. `max_text` и `max_lines` (см.
"Длинные письма") действуют для любого пресета. `slack-webhook` публикует
`{"text": ...}` в Slack mrkdwn с экранированными `&`, `<` и `>`;
`generic-json` публикует `{"subject": ..., "body": ..., "hostname": ...}`.
`[target.<name>.headers]` добавляет заголовки запроса после Content-Type,
так что `Content-Type` там его заменяет; имя заголовка, которое не
годится в токен HTTP, значение с переводом строки или NUL, `Host`,
`Content-Length`, `Transfer-Encoding` или `Trailer`, которые HTTP-клиент
ставит сам и отбросил бы, и `Connection`, `Keep-Alive`,
`Proxy-Connection` или `Upgrade`, которые HTTP/2 не передаёт, дают код
выхода 78. `path` дописывается к пути `url`, а `[target.<name>.query]`
добавляет свои значения, закодированные, к параметрам запроса `url`
после тех, что в `url` уже есть. Значения `headers`, `query` и `path` -
шаблоны (см. [Шаблоны](../templates.ru.md)), которые выполняются для
каждого письма; схема, хост и порт берутся только из `url` или
`url_file`. Путь, который получился пустым, ничего не дописывает, и
запрос идёт на `url` как есть. Путь, который не начинается с одного `/`,
содержит `?`, `#`, обратную косую черту, управляющий символ или сегмент
`.` или `..` (экранированный один или два раза или с параметром после
`;`), или значение заголовка с переводом строки или NUL дают постоянную
ошибку цели до всякого запроса; экранированный `/` в пути остаётся
экранированным. То, что `path` пишет до первого действия `{{ }}`,
проверяется по этим правилам при загрузке конфигурации, код выхода 78.
Значение из письма попадает в сегмент пути через `pathSegment`, которая
экранирует и `/`, но не точки: значение `.` или `..` или с
`/../` всё равно даёт ошибку цели для этого письма. Текст значений
заголовков и параметров запроса вне действий `{{ }}` длиной 8 символов
и больше, а также учётные данные после схемы вроде `Bearer`
маскируются в журнале, как токены; так же маскируется каждый кусок
текста `path` вне действий между двумя косыми чертами длиной 16
символов и больше, как записан и после снятия экранирования.
Переход по перенаправлению не выполняется и считается постоянной
ошибкой, `redirect to https://host not followed` только со схемой и
хостом из Location: путь в нём повторяет путь цели, где топик или
ключ - секрет любой длины. То же верно для любого типа цели, включая
`shoutrrr`.
