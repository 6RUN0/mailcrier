# Шаблоны

Свои шаблоны заменяют встроенный текст цели: ключи `template` и
`template_file`, данные и функции, доступные шаблону, и что происходит,
когда шаблон не сработал или слишком длинный. Разобранный пример -
[`packaging/examples/templates.conf`](../packaging/examples/templates.conf).

```toml
[target.ops-telegram]
type = "telegram"
token_file = "/etc/mailcrier.d/telegram.token"
chat_id = -1001234567890
template = '''
<b>{{ .Subject | default .Strings.NoSubject | tgHTML }}</b>
<i>{{ .Hostname | tgHTML }}</i> {{ .Date | tz "Europe/Berlin" | date "15:04" }}
<pre>{{ .Body | default .Strings.EmptyBody | trimEnd | tgHTML }}</pre>'''

[target.api]
type = "http"
url = "https://api.example.org/notify"
template = '''
{"title": {{ toJson .Subject }}, "host": {{ toJson .Hostname }},
 "text": {{ toJson .Body }}}'''
```

- `template`, шаблон Go `text/template`
  (<https://pkg.go.dev/text/template>), заменяет встроенный шаблон цели
  любого типа, кроме `exec`; `template_file`, абсолютный путь, задаёт
  файл с шаблоном, который читается при загрузке конфигурации, без
  перевода строки в конце. Оба
  сразу нельзя; пустой шаблон или файл даёт код выхода 78. Цель `http`
  принимает ровно одно из двух, `preset` или шаблон, поэтому `username`
  и `channel` с шаблоном недоступны.
- Шаблон пишет разметку цели: Telegram HTML (режим разбора Bot API -
  HTML, другого нет), markdown Discord, mrkdwn Slack, простой текст ntfy
  (заголовком остаётся тема) и `shoutrrr`, тело запроса JSON для `http`,
  которое отправляется с `Content-Type: application/json`, если его не
  заменяет заголовок. Всё, что взято из письма, написал его автор, и всё
  это проходит через экранирование этой разметки: `tgHTML`;
  `discordEscape`, `discordCode` внутри блока кода; `slackEscape`,
  `slackCode`; `mmEscape`, `mmCode` для markdown Mattermost; `toJson` для
  значения JSON.
- Секреты не пишутся внутри действий `{{ }}`: ошибка цитирует действие,
  в котором произошла, и попадает в журнал. Токену место в заголовке, в
  URL или в тексте шаблона вне действий, который ни одна ошибка не
  цитирует.
- Шаблон, который не разбирается, вызывает неизвестную функцию или
  использует `define`, `template` или `block`, отклоняет конфигурацию:
  код выхода 78, письмо задерживается, а запись `configuration rejected`
  называет цель и строку в шаблоне.

## Данные

Поля, которые читает шаблон:

| Поле | Содержимое |
|---|---|
| `.Subject` | декодированный заголовок Subject, пустой, если у письма его нет |
| `.From` | адрес From, иначе отправитель конверта: `.From.Name`, `.From.Addr`, `.From.String` |
| `.Sender`, `.SenderName` | отправитель конверта и имя из `-F` |
| `.To`, `.Cc` | адреса заголовков, как у `.From` |
| `.Recipients` | получатели конверта без адресов, названных только в Bcc или Resent-Bcc |
| `.Date`, `.ReceivedAt` | заголовок Date (без него - время приёма) и время приёма |
| `.MessageID` | заголовок Message-ID |
| `.Headers` | все поля заголовка, кроме Bcc и Resent-Bcc: `.Headers.Get "X-Cron-Env"` (первое значение), `.Headers.Values` (все), `.Headers.Has`, `.Headers.Names`, имена в любом регистре |
| `.Body`, `.BodyHTML` | текст и часть HTML, если она есть |
| `.Attachments`, `.MoreAttachments` | `.Name`, `.ContentType`, `.Size`, `.IsSkipped` (в списке, но не отправлено) каждого перечисленного вложения и число не вошедших в список |
| `.Hostname`, `.Target`, `.Limit` | имя хоста, имя цели, лимит текста цели (0: нет) |
| `.IsCollapsed` | обрезанное тело должно идти в свёрнутом блоке (`on_long = "blockquote"`) |
| `.Strings` | уведомления из `[strings]`: `.Strings.NoSubject`, `.Strings.EmptyBody`, `.Strings.Truncated`, `.Strings.MoreAttachments`, `.Strings.NotSent` |

## Функции

Функции, кроме функций `text/template` (`printf`, `len`, `index`,
`urlquery` и остальных):

| Функция | Результат |
|---|---|
| `toUpper`, `toLower`, `trimSpace`, `trimEnd`, `title` | строка заглавными буквами, строчными буквами, без пробельных символов по краям, без них в конце, с заглавной первой буквой каждого слова и остальными без изменений |
| `default D V` | `V` или `D`, если `V` пустое или только из пробельных символов |
| `join SEP LIST` | строки или адреса `LIST`, соединённые через `SEP`: `{{ .To \| join ", " }}` |
| `match RE S`, `reReplaceAll RE REPL S` | находит ли регулярное выражение Go `RE` совпадение в `S`; `S`, где каждое совпадение заменено, `$1` в `REPL` - группа |
| `tz ZONE T`, `date LAYOUT T` | `T` в зоне IANA `ZONE`, взятой из базы часовых поясов системы, без которой любая зона, кроме `UTC` и `Local`, ломает шаблон, как и неизвестная; `T` в формате Go: `{{ .Date \| tz "UTC" \| date "2006-01-02 15:04" }}` |
| `lines S`, `head N S`, `tail N S` | строки `S` для `range`; её первые и последние `N` строк |
| `truncate N S` | `S`, обрезанная до `N` символов, последние три из которых `...`; без них, если `N` равно 3 или меньше |
| `indent N S` | `N` пробелов перед каждой строкой `S` |
| `humanizeBytes N` | размер: `1.5 KiB` |
| `toJson V` | `V` как значение JSON, всегда корректное |
| `pathSegment S` | `S`, экранированная для одного сегмента пути URL, включая `/` |
| `tgHTML`, `discordEscape`, `discordCode`, `slackEscape`, `slackCode`, `mmEscape`, `mmCode` | экранирование разметок, перечисленных выше |

## Обрезка и лимиты

- Текст обрезается до лимита цели так же, как встроенный (см. [Длинные
  письма](long-messages.ru.md#как-режется-текст)): обрезаются тема,
  вложения и тело, и шаблон выполняется заново. Это работает для
  шаблона, текст которого растёт вместе с ними; то, что шаблон добавляет
  сам, обрезается жёстко, а если тело `http` вообще не помещается в
  `max_text`, шаблон не срабатывает.
- При обрезке длинного текста шаблон выполняется снова и снова, до
  нескольких десятков раз. Все выполнения шаблона для текста одного письма
  для одной цели вместе могут занять 2 с и заканчиваются не позже
  `deadline`, а каждое - 1 с и 1 MiB вывода. Сверх 1 MiB текст с лимитом
  считается слишком длинным, и его тело обрезается с предупреждением
  `template output limit reached`; без лимита (`http` без `max_text`,
  `shoutrrr`) шаблон не срабатывает. Шаблон, остановленный во время
  выполнения любым из ограничений по времени, остаётся неработающим до конца
  вызова или прогона очереди, чтобы каждое следующее письмо сразу получало
  встроенный шаблон. Выполнение, которое должно начаться после того, как
  время истрачено, не запускается: это письмо получает встроенный шаблон, а
  сам шаблон остаётся в работе.

## Когда шаблон не сработал

- Шаблон, который не сработал на письме (ошибка функции,
  ограничение по времени или размеру, текст только из пробельных
  символов, тело `http` больше `max_text`), оставляет этому письму
  встроенный шаблон цели, а журнал записывает
  `template failed, built-in used` (warning) с `target` и `err`;
  код выхода следует доставке: 0, если цель приняла письмо. Цель
  Telegram, которая отвечает 400 на текст шаблона, один раз получает
  текст встроенного шаблона, с той же записью, прежде чем полный текст
  уйдёт только файлом (см. [Длинные письма](long-messages.ru.md)).
- Шаблоны пути, строки запроса и заголовков цели `http` (см. [HTTP и
  Mattermost](targets/http.ru.md)) выполняются с теми же
  ограничениями и из того же бюджета, что и текст; каждый может не
  вывести ничего, и тогда значение остаётся пустым. Встроенного шаблона
  на замену у них нет: если один из них не сработал, цель получает
  постоянную ошибку и ничего не получает для этого письма, а журнал
  записывает `request template failed, message not sent`
  (warning) с `target` и `err`. Ошибка разбора одного из них
  называет `<target>.path`, `<target>.query.<name>` или
  `<target>.headers.<name>` и его строку.
